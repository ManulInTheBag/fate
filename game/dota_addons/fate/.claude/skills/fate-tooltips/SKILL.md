# Тултипы способностей (fate)

Полный свод правил — `правила описаний.txt` в корне аддона; **прочитать его
перед первой правкой**, здесь — рабочий порядок и грабли. Эталонные герои, по
которым равняться: Okada Izo, Ozymandias.

## Порядок работы

1. **Начать с KV, а не с локализации.** Открыть
   `scripts/npc/heroes/npc_fate_hero_<hero>.kv`, выписать `Ability1..N` и
   `Attribute1..N` — это порядок Q/W/E/D/F/R и реальный список того, что описывать.
   Способности, выдаваемые в рантайме, в hero.kv не значатся — их искать по папке
   `scripts/vscripts/abilities/<hero>/`.
2. Для каждой способности открыть её блок в
   `scripts/npc/abilities/<hero>/<hero>_abilities.kv` и **её Lua**. Источник
   правды по механике — Lua, а не старый тултип.
3. **Расхождение KV ↔ Lua чинить сразу**, а не описывать по факту: если Lua
   считает от захардкоженного числа, вынести его в `AbilityValues` и читать
   `GetSpecialValueFor`. Иначе тултип обречён врать после первого баланса.
4. Писать описание в `resource/addon_english.txt`. `addon_schinese.txt` — в
   **UTF-16**, ключ необязателен (падает на английский), но если правишь — не
   ломать кодировку файла.

## Ключи

```
"DOTA_Tooltip_Ability_<ability>"              "Имя способности"
"DOTA_Tooltip_Ability_<ability>_Description"  "Тело"
"DOTA_Tooltip_Ability_<ability>_<key>"        "Подпись значения:"
"DOTA_Tooltip_Ability_<ability>_Note0"        "Сноска"
"DOTA_Tooltip_modifier_<modifier>"            "Имя баффа"
"DOTA_Tooltip_modifier_<modifier>_Description" "Что делает"
```

Строка значения рисуется, только если `<key>` есть в `AbilityValues` **этой**
способности. Подпись кончается двоеточием (`"Dash speed:"`); ведущий `%` в
подписи заставляет игру дописать знак процента к значению (`"%Slow:"`).

## Шапка описания (первая строка, всегда)

```
Cast Point: <font color='#FFFAFA'>%AbilityCastPoint%</font>s    |    <font color='#29EE32'>Refreshable</font><br><br>
Cast Point: <font color='#7FFF00'>immediate</font>    |    <font color='#EE5C29'>Unrefreshable</font><br><br>
<font color='#FFFAFA'>PASSIVE</font><br><br>
```

- `%AbilityCastPoint%` — токен движка, никогда не число руками; «s» вне тега.
- Разделитель: 4 пробела, `|`, 4 пробела.
- Refreshable/Unrefreshable определяется списком `CannotReset` в
  `scripts/vscripts/libraries/util.lua` — **проверить, не угадывать**.
- У атрибутов (`*_sa_*`) и комбо шапки НЕТ.

## Цвета (главное)

| Что | Цвет |
|---|---|
| физ. урон, броня | `#A72E28` |
| маг. урон, мана, магсопр | `#58ACFA` |
| чистый урон | `#D1A951` |
| хил, ХП, реген | `#ACFF05` |
| STR / AGI / INT | `#FF0000` / `#00FF00` / `#1E90FF` |
| просто важные цифры | `#FFFAFA` |
| мягкие дебафы (слоу, рут, dimensional lock, слепота) | `#9400D3` |
| жёсткие (стан, сайленс, мут, revoke, кнокбэк, страх, чарм) | `#FF3399` |
| снижение хила (с указанием тира) | `#7F00FF` |
| сильные бафы | `#ff9900` |
| имена способностей и саммонов, шапка комбо | `#58ACFA` |
| именные состояния героя (Manslayer, Berserked) | `#FF0000` |
| «Upgradable/Unlockable by attribute X.» | `#F1C40F` |
| подзаголовки Passive/Active внутри описания | `#FFFFFF` |

## Комбо

Первые две строки всегда:
```
<font color='#58ACFA'>Combo Requirement : 30 all stats</font>\n
<font color='#58ACFA'>Combo Sequence : autocast W - F in 3 seconds</font>\n
```
Последовательность сверять с Lua комбо-способности, а не с легендой.

## Стиль

- Имя героя целиком и единообразно (Oda Nobunaga, не «nobu»).
- Переносы: `\n` **или** `<br>` — не мешать в одном описании.
- Никогда не хардкодить число, которое есть в `AbilityValues` — инлайнить `%key%`.
- ⚠️ Инлайнить можно **только свои** ключи. Значение чужой способности — только
  простым текстом (иначе покажется пустота).
- `%%` печатает знак процента.
- Взаимодействующие способности упоминать по имени в `#58ACFA`.

## Правка файлов
`addon_english.txt` — UTF-8/CRLF, править **точечно**. Не переписывать целиком
через PowerShell `Get-Content`/`Set-Content`: кириллица и китайский умирают,
а смешанные окончания строк делают весь файл «изменённым» в git.
