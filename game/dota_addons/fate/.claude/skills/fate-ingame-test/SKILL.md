# Проверка способностей в игре (fate, Dota Tools + computer use)

Скрипты лежат в `scripts/` рядом с этим файлом (дальше `$S`):
`dota_windows.ps1` — окна и фокус, `console_log.py` — лог консоли,
`zone_debug.py` + `zone_debug.lua` — отрисовка зон попадания.

## 0. Доступ и окна

- `request_access` на **`dota2.exe`** и **`vconsole2.exe`** (именно имена exe: окно игры,
  Asset Browser и Particle Editor принадлежат `dota2.exe`, консоль — отдельный процесс).
  «Dota 2» из меню Пуск — это Steam-ярлык: `open_application` на нём запускает ВТОРОЙ
  экземпляр и ловит «Only one instance…». Его не трогать.
- Состояние: `powershell -File $S/dota_windows.ps1`. Фокус:
  `-Focus game | console | assets`. Скрипт разворачивает только СВЁРНУТОЕ окно:
  повторный restore превращает VConsole в маленькое окно, и поле Command уезжает.
- Tools не запущены — попросить юзера запустить (или `dota2.exe -addon fate -tools -steam
  -console -condebug`, только с его согласия). На старте бывает окно «Legacy Compiled
  Data»: закрыть крестиком, **Fix Selected Assets не жать**.

## 1. Консоль и перезагрузка

- VConsole открывается `\` в окне игры. Перед вводом сделать скриншот и найти поле
  **Command** внизу окна, его место меняется вместе с размером окна.
- Консольного Lua **нет**: `script` и `script_execute` в этой сборке отсутствуют. Код в
  игру попадает только файлом + `script_reload` (см. §4).
- `script_reload` перезагружает **только сервер**. Клиентская VM (эффекты модификаторов,
  метки «Оглушение», иконки, `GetTexture`) перезагружается командой **`cl_script_reload`**.
  Если файл упал на клиенте при старте матча, его модификаторы на клиенте «not found»
  до этой команды: урон идёт, а визуала нет.
- Дошла ли команда: `python $S/console_log.py reload`. Там должно быть свежее
  «Initializing script VM» и список ошибок после него.
  `addon_game_mode.lua:6144 concatenate 'err'` — давний безвредный шум, скрипт его не показывает.
- ⚠️ **Новый ключ в AbilityValues** уже созданная способность не видит
  (`GetSpecialValueFor` → 0) даже после reload. Проверять только в новом матче.
  Правка значений существующих ключей тоже надёжна только в новом матче.
- ⚠️ Таймеры библиотеки `Timers` **переживают** `script_reload`. Зацикленный
  отладочный таймер гасить флагом в `_G`, удаления файла мало.

## 2. Матч и герой

1. В VConsole: `dota_launch_custom_game fate fate_ffa`, затем
   `python $S/console_log.py wait "officially begun" --timeout 150`.
2. Экран пика: клик по портрету выбирает только превью, выбор делает кнопка
   **SELECT** внизу по центру (~ x 686, y 790 на 1456×819). Barghest — 12-й портрет
   первого ряда. Пока идёт «LOADING…», клики по сетке не работают.
3. Чит-панель слева: **LVL MAX** (героя выделить), **+ DUMMY TARGET** (манекен
   появляется ПОД героем, отойти правым кликом), **Free Spells** (чекбокс под
   «GLOBAL SETTINGS», его частично перекрывает ряд иконок; включилось ли, проверять).
4. Вкачать способности: `ctrl+q` / `ctrl+w` / `ctrl+e` / `ctrl+r` по 5 раз.
5. Без Free Spells у связок есть кулдаун между ударами: у Q Barghest пауза ≥ 1.3 с,
   иначе второе нажатие молча съедается.
6. Открытый чат (после `\` или Enter) крадёт клавиши. Закрыть через `Return`.
   `Escape` его не закрывает.

## 3. Кадры

- Эффекты живут 0.2–1 с, скриншот идёт ~0.15 с. Серия `zoom` (scale 0.3–0.6) по
  области вокруг героя внутри одного `computer_batch` надёжнее одиночного кадра.
- Каст и кадры класть в ОДИН batch: `mouse_move` на цель → клавиша → `wait` → серия zoom.
- Курсор увести с HUD (например `mouse_move 1350,250`), иначе висит тултип способности.
- Два эффекта в одну секунду смешиваются (удар Q2 и сразу R2): разводить паузой ≥ 2 с.
- Кольца-«мазки» (`barghest_slash_2` и похожие) за ~0.3 с обегают круг. На одном кадре
  видна только дуга, это не баг.
- Манекен стоит вплотную: полоски HP героя и цели перекрываются, и метку
  («Оглушение», «Оцепенение») легко приписать не тому. Отходить на 150–200.

## 4. Отрисовка зон попадания

```
python $S/zone_debug.py on abilities/barghest/barghest_shared.lua barghest --skip barghest_shared,barghest_f --min 201
```
(`--min 201` у Barghest прячет покадровую проверку остановки рывка Q2 (R=200),
иначе вдоль пути рисуется «гусеница» кругов. Нужна именно она — ставить 150.)
затем `script_reload`. Цвета: **зелёный** — `FindUnitsInRadius`, **жёлтый** —
`FindUnitsInLine`, **красный** — дуги/секторы, **синий** — полосы (адаптеры хелперов Слуги).
Картинка держится 3 с, в консоль идут `[ZT] …` с числами и `файл:строка`:
`python $S/console_log.py tail --grep "\[ZT\]"`.

- `host` — общий модуль Слуги (или любой файл её способности). **Не** `addon_game_mode.lua`.
- `--skip` — общие хелперы (их рисует адаптер, иначе будет двойная картинка) и пассивки,
  которые ищут цели каждый тик (у Barghest F — круг 1000).
- Новый Слуга со своими `*_FindInArc`-хелперами: дописать адаптер в конце `zone_debug.lua`
  по образцу блока Barghest.
- **Снять**: `python $S/zone_debug.py off` + `script_reload`. `status` покажет, осталось ли что-то.

### Изолированный показ эффекта

Если эффект смешивается с другими или его надо разобрать по частям, временно
допиши в конец `zz_zone_debug.lua` таймер, который каждые 2.5–3 с спавнит ровно
этот партикль (или вызывает метод визуала способности) у героя
`PlayerResource:GetSelectedHeroEntity(0)`, рядом рисует зону и подпись
`DebugDrawText`, а варианты чередует (привязка follow/world, по одному эффекту).
Таймер гасить флагом (`_G.X_ON = false` + reload), см. §1.
Визуал способности заранее выносить в отдельный метод (`barghest_r:FxUppercut`),
чтобы тест вызывал тот же код, что и сама способность.

## 5. Particle Editor

Asset Browser (`-Focus assets`): вкладка **All Assets**, тип **Particle System** → Only,
фильтр по имени, двойной клик. Контрольные точки превью задаются справа (Point #N).
Камера превью колесо не слушает: для замеров полезнее изолированный спавн в игре (§4).
Структуру vpcf быстрее смотреть текстом: `grep m_nControlPoint`, поля `C_INIT_RingWave`.

## 6. Уборка (обязательно)

1. `python $S/zone_debug.py off` + `script_reload`. Если ставил изолированные таймеры, сначала погасить их флагом.
2. Временные `print` в коде способностей убрать: помечать их `[ZT_TMP]` и потом
   `grep -rn ZT_TMP scripts/vscripts`.
3. Игру и Tools не закрывать без просьбы: юзер может продолжать тестировать.
4. Итог записать в память Слуги: что проверено в игре и чем именно.

## Чек-лист частых находок

- Эффект не совпадает с зоной: размер клинковых партиклей задаёт CP5 (`Barghest_FxSize`),
  угол дуги не управляется, вспышки (`*_slam`, `*_explosion`) из CP размер не берут.
- Стан есть, метки нет: у своего модификатора нет `IsStunDebuff() → true`, либо файл
  не загрузился на клиенте (`[Client] … was not found!` в логе → `cl_script_reload`).
- `OnDestroy`/`OnCreated` без `IsServer()` сыплют ошибками клиента (`EndCooldown` nil и т.п.).
- `MODIFIER_STATE_DEBUFF_IMMUNE` в этой сборке **не отбрасывает** дебафф: модификатор
  ложится, а его состояние глушится, пока иммунитет висит. Кончился иммунитет — стан
  досиживает остаток. Проверять не наличием модификатора, а `IsStunned()`.
  Контроль для теста можно вешать кастером-врагом (манекеном) через таймер в
  отладочном файле, см. §4.
- Таблица с ключом-константой движка (`[DOTA_UNIT_ORDER_…] = true`): одна пропавшая
  константа роняет загрузку всего файла («table index is nil»), способность исчезает.
