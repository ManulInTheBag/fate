# Ревью на краши и утечки (fate)

Каждый пункт — реально пойманный в этом проекте баг, а не общая теория. Проверять
по изменённым файлам грепом, а не на глаз.

## 1. Реентрантность damage-пайплайна — краш сервера

Внутри `GetModifierIncomingDamage_Percentage`, `GetModifierIncomingPhysicalDamage*`,
`GetModifierTotal_ConstantBlock` и вообще любого хука, вызываемого движком
**во время расчёта урона**, нельзя синхронно звать `ApplyDamage`/`DoDamage`,
`RemoveSelf`/`Destroy`, `AddNewModifier` на цели. Движок падает без внятного лога.

Правильно: отложить на `Timers:CreateTimer(0, function() ... end)` и внутри
гардить хендлы (пункт 2).

Грепать: в файле есть `GetModifierIncoming` → проверить тело на `DoDamage(`,
`ApplyDamage(`, `RemoveSelf(`, `ForceKill(`.

## 2. Протухшие хендлы в отложенных колбэках

Любой `Timers:CreateTimer` и `ProjectileManager`-колбэк исполняется позже, когда
юнит/партикль уже мог умереть или конец раунда мог всё снести.

```lua
Timers:CreateTimer(1.0, function()
    if not IsNotNull(unit) then return end   -- НЕ голое `if unit then`
    ...
end)
```

`if unit then` истинно и для убитого хендла — падает уже на первом методе.
`IsNotNull` из `libraries/util.lua`. Аналогично для `self`/`ability` в длинных
таймерах и для элементов таблиц целей, которые кто-то мог занулить.

## 3. Утечки dummy-юнитов

Дамми под партиклы/вижн/якорь эффекта должны умирать **всегда**, а не по «жёсткому»
таймеру рядом с длительностью способности:
- вешать `modifier_kill` с запасом ИЛИ собирать созданных в таблицу на кастере и
  удалять в функции завершения;
- отдельная ветка на «кастер умер во время каста/чанта»: функция завершения тогда
  не вызывается никогда, а юниты уже наспавнены (классика — миры UBW/AOTK);
- `RemoveSelf()` на уже мёртвом дамми = см. пункт 2.

Признак в игре: невидимые неселектабельные юниты, накапливающиеся между раундами.

## 4. Партиклы

- Каждый `ParticleManager:CreateParticle` обязан иметь парный
  `ReleaseParticleIndex` (после `DestroyParticle(idx, false/true)`); без релиза
  индексы копятся всю игру.
- Партикль, привязанный к юниту через `PATTACH_*_FOLLOW`, надо убивать в
  `OnDestroy` модификатора, а не по таймеру.
- Не прекешенный `.vpcf` = просто ничего не видно, без ошибок. Проверить, что
  путь покрыт одним из трёх способов precache (см. скилл `fate-ability`).
- `ACT_DOTA_..._8/9` не существуют как глобальные константы — вылет по nil.

## 5. Завершение «мировых» и длительных способностей

Флаг активности (`IsUBWActive` и подобные) сбрасывать **первой строкой**
End-функции и там же выходить, если он уже снят. Иначе смерть кастера даёт двойной
тир-даун (`OnOwnerDied` способности + `OnDestroy` модификатора с `RemoveOnDeath`),
второй проход идёт по уже занулённым таблицам и раскидывает юнитов по мусорным
координатам. Проверять на ложность (`if not flag`), а не `== false` — `nil` не
ловится.

`emiya_unlimited_bladeworks.lua` и `iskander_ionioi.lua` — копипаст-близнецы:
баг, найденный в одном, почти всегда есть и во втором под другим именем переменной.

## 6. Диспел и статусы

Новый модификатор должен быть прописан в одной из таблиц
`softdispellable/strongdispellable/deargdispellable/cleansable` в
`libraries/util.lua` — иначе он молча не снимается ничем. Слоу — ещё и в
`slowmodifier`. Дебафы вешать после `IsSpellBlocked(target, caster)`.

## 7. Идентификация героя в рантайме

`caster:GetUnitName()` из-за `override_hero` возвращает **базового дотовского
героя** (`npc_dota_hero_juggernaut` у Сасаки), а не имя Слуги. Гейт
`GetUnitName() == "npc_dota_hero_false_assassin"` всегда ложен и молча выключает
код. Сверять с `override_hero` из `scripts/npc/heroes/npc_fate_hero_<hero>.kv`.

## 8. Дедик ведёт себя иначе

На выделенном сервере `debug` = nil (любой `debug.traceback` в обработчике = вылет)
и консоль не видна. Диагностировать через брейдкрамбы `FateCrumb`, а не через
печать в консоль. Баг, не воспроизводящийся локально, — первым делом сюда.

## Как отдавать результат
Список находок с путями `файл:строка`, самое опасное первым: краш → утечка →
косметика. Не чинить молча то, о чём не просили: сначала показать список.
